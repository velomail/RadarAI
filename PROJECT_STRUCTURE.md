# Project structure

Two **independent** stacks in one repo. They share RapidAPI/OpenAI keys in practice but use **different env files** and **different code paths**.

```
n8n-job-funnel/
├── web/                    ← SaaS app (deploy this folder to Vercel)
│   ├── app/                ← Next.js routes
│   ├── components/         ← UI + auth forms
│   ├── lib/engine/         ← Job radar pipeline (no n8n)
│   ├── lib/supabase/       ← Auth clients
│   └── scripts/            ← deploy-vercel.mjs, test-resend.mjs
├── db/migrations/          ← Supabase SQL (run in order)
├── docs/                   ← Ops + auth + monetization (see docs/README.md)
├── scripts/                ← sync-saas-env.mjs (root .env.old → web/.env.local)
├── personal/               ← Optional local n8n funnel (separate from SaaS)
├── package.json            ← saas:* and personal:* npm scripts
└── PROJECT_STRUCTURE.md    ← You are here
```

## Which folder do I work in?

| Goal | Directory | Env file | Start command |
|---|---|---|---|
| Ship / develop the SaaS app | `web/` | `web/.env.local` | `npm run saas:dev` (from root) or `cd web && npm run dev` |
| Run the old n8n Telegram funnel | `personal/` | `personal/.env` | `npm run personal:up` then `npm run personal:deploy` |
| Change database schema | `db/migrations/` | — | Run SQL in Supabase dashboard |
| Deploy SaaS to production | — | Vercel project env vars | Push to Git; root = `web/` |

## Env files (do not mix these up)

| File | Used by | Committed? |
|---|---|---|
| `web/.env.local` | Next.js dev + mirrors Vercel prod vars | No |
| `personal/.env` | Docker n8n + deploy script | No |
| `.env.old` at repo root | **Legacy backup only.** Use `npm run saas:sync-env` to copy into `web/.env.local`. | No |

If you still have a root `.env`, run `npm run saas:sync-env` (copies to `web/.env.local`), then rename the root file to `.env.old` so you are not editing the wrong one.

## Cleanup & disk use

| Item | Safe to delete? | Command |
|---|---|---|
| `web/.next/` | Yes (rebuilt on dev/build) | `npm run saas:clean` or `npm run saas:dev:clean` |
| `web/tsconfig.tsbuildinfo` | Yes | included in `saas:clean` |
| `.env.old` at repo root | Yes **after** confirming `web/.env.local` is current | manual delete |
| `personal/data/`, generated workflow | Yes (regenerated by n8n) | already gitignored |

Do **not** run `npm run saas:build` while `npm run saas:dev` is running — it corrupts `.next` and causes 500 errors.

## Root npm scripts

```bash
npm run saas:clean         # remove .next + tsbuildinfo
npm run saas:dev           # Next.js on :3000
npm run saas:dev:clean     # clean + dev server
npm run saas:preview-email # sample HTML to stdout
npm run saas:build        # production build check
npm run saas:typecheck    # tsc
npm run saas:sync-env     # copy .env.old → web/.env.local
npm run saas:logs         # tail Vercel production logs
npm run saas:deploy:only  # redeploy without env upload loop
npm run saas:engine:mock  # Vercel → mock job data (then redeploy)
npm run saas:engine:live  # Vercel → real APIs (then redeploy)
npm run personal:up       # docker n8n :5678
npm run personal:down
npm run personal:deploy   # push workflow to local n8n
```
